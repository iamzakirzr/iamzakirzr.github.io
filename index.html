about

What I actually do

I'm a Senior QA Engineer at IQVIA, working on healthcare and life sciences platforms where "it looked fine when I clicked it" is not an acceptable standard of evidence. Most of my career has gone into building test automation frameworks that other engineers can actually live in: Playwright, Selenium, Cypress, AccelQ, Python and C#, wired into Azure DevOps so the regression suite runs itself every day instead of the night before a release.

The newer half of the job is the interesting one. Enterprise chatbots, RAG pipelines and agentic workflows don't fail like deterministic software does: they fail quietly, fluently, and only sometimes. So I build evaluation frameworks instead of assertions: golden datasets, scored metrics, thresholds a pipeline can fail on. A drop in faithfulness gets handled the same way I'd handle a red test.

I also lead a team of five QA engineers and own the STLC across Scrum, Kanban and Waterfall delivery models, which mostly means translating between what a test report says and what a release manager needs to hear.

How I build test automation

Four things I keep getting hired to do, in the order they matter.

Framework design

Page Object Model is the design every framework I build sits on. Locators and page behaviour live in one place, so a UI change is one edit instead of fifty, and the tests above read as intent rather than selectors. Reusable libraries sit under that, shared across suites, which is what makes a new test cost hours rather than days.

The same design carries across Playwright, Selenium and Cypress on the web, and Squish and AccelQ beyond it, in Python and C# alike. Built to be something other engineers can work in rather than around.

PlaywrightSeleniumCypressPythonC#/.NETPyTestNUnitAccelQ

One suite, every layer

A Python and Playwright framework validating UI, API and database in the same run. Contract and schema checks sit under the UI tests, and SQL-level assertions catch data-integrity faults directly instead of letting them surface later as a confusing screen.

Where the system is event-driven, that extends to the message layer: asserting what actually lands on a Kafka topic, and how consumers behave once it does. A queue that silently drops a message fails no UI test, which is exactly why it needs its own.

UIAPI contractsKafkaEvent streamsSQL validationJavaScriptTypeScript

Pipelines and execution

Azure DevOps running full regression nightly, GitHub Actions giving pull requests their own feedback loop, and Jenkins driving a 20-machine grid for cross-platform runs. Suites also execute against Kubernetes environments, so what passes in CI resembles what ships.

Azure DevOpsGitHub ActionsJenkinsKubernetesDockerPR validation

Scale, platforms and load

Performance and scalability work through JMeter, Artillery and k6 against APIs under load. Coverage reaches past the browser too: Windows, macOS and iOS desktop clients through Squish, and mobile through Appium.

ai quality engineering

Testing systems that don't behave the same way twice

A model that is fluent and wrong passes every assertion you'd write for ordinary software. These are the four checks that catch it.

LLM & RAG evaluation

Golden datasets first, then scored runs against faithfulness, context precision, answer relevance and hallucination rate. DeepEval and RAGAS sit in the loop so a drop in response quality surfaces as a failing check rather than a support ticket three weeks later.

RAGASDeepEvalGolden datasetsContext precision

Agentic workflow validation

Multi-step agents get judged on what they did, not what they said: tool-calling accuracy, reasoning traces, autonomous task execution, and whether context is still intact by step six.

Tool-callingReasoning tracesContext retentionLangSmith

Conversational AI quality

End-to-end quality engineering for enterprise chatbots: conversational flows, intent recognition, and fallback behaviour when the model has nothing useful to say. Deterministic guardrails catch the contract violations a pattern can express. Semantic scoring covers the far larger set it can't.

Intent recognitionFallback pathsRegex guardrailsFlow coverage

Robustness & safety

Prompt-injection probing and bias testing, sweeping temperature, confidence thresholds and context memory to find the point where a model stops being trustworthy. Better that I find it than a user does.

Prompt injectionBias testingParameter sweepsModel robustness
